# Create `/test_infinity_form`

Create a new process named `/test_infinity_form`.

The process should have one start variable:

- `$position` — `object`

Use this schema:

```json
{
  "type": "object",
  "properties": {
    "x": {
      "type": "number"
    },
    "y": {
      "type": "number"
    }
  },
  "required": ["x", "y"]
}
```

Example value:

```json
{
  "x": 120,
  "y": 80
}
```

Create another variable:

- `$renderInfo` — `object`

Use this schema:

```json
{
  "type": "object",
  "properties": {
    "processedAt": {
      "type": "string"
    },
    "distanceFromCenter": {
      "type": "number"
    }
  },
  "required": ["processedAt", "distanceFromCenter"]
}
```

## Start form

Add a start form that collects the initial X and Y coordinates.

Keep it minimal:

- one number input for X;
- one number input for Y;
- one button to start the process;
- validation that both values are provided.

Submit the coordinates as `$position`:

```js
try {
  await ailaflow.submitForm({
    position: {
      x,
      y
    }
  });
} catch (error) {
  // Display a simple error to the user with details.
}
```

In the Start form, `submitForm()` starts the initial `/test_infinity_form` process execution using the submitted `$position`.

## Script step

Add a **Script** step before the Finish step.

The script should demonstrate that process logic executes before each output form is rendered.

Read `$position`, calculate the rectangle's distance from the center of the `300 × 300` canvas, and write the result together with the current timestamp to `$renderInfo`.

```js
const ailaflow = require('@ailaflow/bridge-lib');

const position = await ailaflow.readVariable('$position');

const centerX = 150;
const centerY = 150;

const distanceFromCenter = Math.sqrt(Math.pow(position.x - centerX, 2) + Math.pow(position.y - centerY, 2));

await ailaflow.writeVariable('$renderInfo', {
  processedAt: new Date().toISOString(),
  distanceFromCenter: Number(distanceFromCenter.toFixed(2))
});
```

The process flow should be:

```text
Start
→ Script: process position
→ Finish + output form
```

## Finish step

Add a **Finish** step that returns:

- `$position`
- `$renderInfo`

Attach a form directly to the Finish step.

### Processed information

At the top of the output form, before the canvas, display information from `$position` and `$renderInfo`.

For example:

```text
Position: 120, 80
Distance from center: 86.02
Processed: 2026-09-17T20:35:12.123Z
```

Keep this section simple and visually separated from the canvas.

Because `$renderInfo.processedAt` is generated by the Script step, every drag should visibly demonstrate that a new process execution occurred and the Script step ran again before the updated output form was rendered.

### Canvas

Below the processed information, render an HTML canvas with a native resolution of:

```text
300 × 300
```

Keep the canvas element's actual coordinate system fixed at `300 × 300`.

The displayed canvas should automatically scale down when necessary to fit the available screen width while preserving its square aspect ratio.

It should never be displayed larger than its native `300 × 300` size.

For example, its CSS behavior should be equivalent to:

```css
canvas {
  width: 100%;
  max-width: 300px;
  height: auto;
}
```

The canvas `width` and `height` attributes must still remain `300`.

Read `$position` and draw a small red rectangle at:

```text
x = position.x
y = position.y
```

Keep the rectangle fully inside the canvas.

Make the rectangle draggable using pointer input so the same implementation works with mouse, touch, and pen where supported.

When processing pointer coordinates, convert displayed screen coordinates into the native `300 × 300` canvas coordinate system.

For example, account for the current displayed size using the canvas bounding rectangle rather than assuming CSS pixels equal canvas pixels.

### Drag interaction

When dragging starts, only begin the drag if the pointer is over the rectangle.

While dragging, update the rectangle visually on the current canvas so movement feels immediate.

Do not start another process execution for every pointer movement.

When the drag ends:

1. calculate the final X and Y coordinates in the native `300 × 300` coordinate system;
2. keep the complete rectangle within the canvas bounds;
3. submit the new `$position`.

From a Finish form, `ailaflow.submitForm()` starts a new execution of the same process.

Use:

```js
try {
  await ailaflow.submitForm({
    position: {
      x: newX,
      y: newY
    }
  });
} catch (error) {
  // Display a simple error to the user with details.
}
```

Disable further drag submissions while this request is being processed so the user cannot accidentally start multiple executions.

The new `/test_infinity_form` execution should:

1. receive the updated `$position`;
2. execute the Script step again;
3. generate new `$renderInfo`;
4. reach the Finish step;
5. render a new output form;
6. display the updated processed information above the canvas;
7. render the rectangle at its new position.

This creates a continuous form loop:

```text
render output form
→ drag rectangle locally
→ release rectangle
→ submitForm()
→ new process execution
→ Script executes
→ new Finish form renders
→ updated information
→ updated canvas
```

The important distinction is:

- pointer movement updates the current canvas locally for responsive dragging;
- releasing the rectangle calls `submitForm()` and starts a new process execution.

## UI

Keep the HTML, CSS, and JavaScript minimal.

The Start and Finish forms should use the same visual style:

- same typography;
- same container width;
- same spacing;
- same input and button styling;
- same error presentation.

Both forms should work well on mobile and desktop.

Keep the output information compact and render it before the canvas.

The canvas must preserve its native `300 × 300` coordinate system even when visually scaled to fit a smaller screen.
